Rule D · a range on a day-sized layout

  • D is today when the range holds today, otherwise the range's first day.
  • Example on a phone: /week/2026-11-02 on Tue 3 Nov → /day/2026-11-03; /week/2026-11-16 → /day/2026-11-16.
  • The address then shows what is on screen, so refresh shows the same thing.

Rule T · a task link lands on the task's date

  • No date (Inbox) → /inbox?task=…. Today → /today?task=…. Any other date, past or upcoming → /day/<date>?task=….
  • The date is read when the link opens, so a task moved since the link was made opens on its new date. Start date in the device's time zone.
  • A repeating task's link names one occurrence (as notifications already do) and opens that occurrence's date, with its own steps and done state (R-09).
  • Not found, deleted or not yours → /today; nothing is said about the id (D2).

Mode and width never change from a link (D4)

  • A link opens the closest place in the layout you are in; the Full / Minimal setting is never changed by a link.
  • Show Less / Show Everything is not a Back step. It keeps the date and the open task (ED-067); Show Everything returns to the Full view you left (Week stays Week), as E-FullA-v2 draws.
  • A web window resized across the phone width re-reads the same address for the new layout (replace).

History, links and the guard

Back · Forward · Refresh (requirement 6)

  • One Back step per view, date or task you open yourself.
  • Redirects replace the entry: /now in Full, /task/…, ranges on phones and in minimal, a mode switch, a resize. No extra step, no Back loop.
  • Closing a task (✕, Esc, swipe down) removes ?task=: a Back step when you opened it here, a replace when you arrived with it open (a shared link).
  • Forward re-opens what Back closed; the task is checked again, and a deleted one leaves the view without it.
  • Refresh shows the same view, date and open task; the task is checked again.
  • Apps keep the same stack: Android Back and predictive back, the iPhone back swipe and Close, the Mac's ⌘[ follow it.

Links that must keep working (requirement 7)

  • dottoday:// links go through the same allow-list as web addresses: widgets (task/ · today · add · inbox), Live Activity (task/ · focus/), the Mac status item (task/ · today), Android shortcuts and tiles (add · today), Share (inbox), Wake Up (wake-up · wake-up/mission/…). All unchanged.
  • Notifications open /task/<occurrence>, /today, /review, /wake-up, /focus/<id>, as built; /task/ now lands on its date (rule T).
  • Sign-in: dottoday://auth-callback?code=… is handled before the allow-list and is never a route (unchanged). On the web the code arrives before the # and Supabase reads it; the router never sees it, which hash URLs keep true.
  • Calendar connect returns to …/#/settings/calendars (web) or dottoday://settings/calendars: unchanged, so the backend's allowed return addresses do not change.

The one guard change (built later, not now)

  • ?task= is accepted only on /now /today /day /3-days /week /month /inbox /search: one key, one value, a lowercase UUID v7.
  • The task is looked up under the signed-in user (the repository already enforces ownership, docs/09 M4.2).
  • Any other query is dropped and the path kept; a bad path still lands on /today. The sign-in callback is untouched.
  • No change to hosting, Supabase, sign-in or calendar configuration.

What the code does today

  • Web URLs are hash URLs: dottoday.app/#/today. No path strategy is set, and the calendar sign-in returns to https://dottoday.app/#/settings/calendars (docs/08), an origin allow-listed in a backend function.
  • The deep-link guard refuses any query or fragment (deep_link_guard.dart, docs/06): ?task= or ?q= would land on /today today.
  • Apps use the same paths through dottoday:// links (iPhone, Android, Mac). No universal / app links.
  • The boards differ: E-FullA-v2 draws path URLs with ?task= and /search?q=; E-Minimal draws /now?task=; E-Workspace drew /plan/day/….

Rules

  • One name per place, the same in the web address, dottoday:// links and the apps' own navigation.
  • A link never changes your mode. It opens the closest place in the mode you are in (D4).
  • Back: each view, date or task change is one step. Show Less / Show Everything is a setting, not a step (ED-078).
  • Switching mode cancels a selection or drag in progress (Undo still works); an open task stays open (ED-086).
  • Refresh restores the view, the date and the open task.
  • Unknown or malformed links land on /today, as built.

Four details to settle inside the recommendation

Each has a recommended answer

D1 · Web URL style

  • A (recommended): keep the built hash URLs, dottoday.app/#/week/2026-11-02. Every link already shared keeps working.
  • B: path URLs, dottoday.app/week/2026-11-02, as E-FullA-v2 draws them.
  • Why A: Path URLs need a rewrite rule on the web host and a new calendar sign-in return address in the backend's allowed origins, which touches the hosted project (a separate, must-ask change). They can come later without renaming any route.

D2 · A task in the address

  • A (recommended): ?task=<id> on any view, as both boards draw. The guard accepts only this one key, only a UUID v7, and looks the task up under the signed-in user; anything else is dropped and the view stays.
  • B: only /task/<id>; refresh opens the task over its day, not over the view you were on.
  • Why A: Refresh and Back keep the view you were on, which is what both boards show. The guard stays strict (docs/06 §9).

D3 · Search text in the address

  • A (recommended): no: /search only; the search box keeps its text for the tab's session.
  • B: /search?q=… (E-FullA-v2).
  • Why A: Search text is often a task title, which this project treats as personal data. URLs end up in browser history, sync and server logs.

D4 · A link to a place your mode hides

  • A (recommended): open the closest place in your mode: Week, 3 Days or a day → Calendar on that date in minimal; /now → Today in Full. The setting never changes.
  • B: open the hidden place for that visit (Full view inside minimal) without changing the setting.
  • Why A: Doc 14: Hidden is a view choice, and nothing but the switch changes it. One rule covers both modes.
