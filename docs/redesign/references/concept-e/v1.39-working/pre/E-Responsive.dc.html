The G4-2 rule (approved, ED-167)
Layout class by the window's available width in logical pixels: compact < 600, medium 600–839, expanded ≥ 840 (unchanged; WidthClass in the app). Never device type or physical resolution.
The task editor floats over Today below 1160. From 1160 it docks only if sidebar, Today and editor all keep their minimum widths. This replaces the old 1100 rule.
Changing between floating and docked moves the same editor. No new instance, no save, no lost text, fields, focus or scroll, and no change to the selected task or date. A proposal is never committed by a resize.
Refinements (approved, ED-168)
H1 · short height. When the window's usable height (after safe areas, not counting the software keyboard) is under 480, use the compact layout and never dock. Platform chrome stays native: a short web window keeps web chrome (mobile-web navigation: G4-5); Mac cannot reach it (minimum 640). Full or Minimal mode never changes.
M · docking minimums. Today 480 (600 above 130 % text), editor 420, sidebar 216. Dock only if these plus dividers, gutters and margins all fit, and never below 1160. The large-text threshold is computed from the real layout, not fixed at 1236.
Drawn at 25 % scale. Schematic: thread, sidebar and editor blocks only; no screen is redesigned. Device behaviour and 200 % text: PENDING verification.
