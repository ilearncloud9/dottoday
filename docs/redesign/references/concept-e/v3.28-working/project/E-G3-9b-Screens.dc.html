Custom colours

what they need
What custom colours need (must-ask before any build)
  • Data: today a task stores only color_key (one of 9 names). Custom colours need a new value (e.g. color_hex, with color_key = custom) and a saved “Your colours” list in settings: a Supabase migration and sync change. Existing tasks keep their keys.
  • Rendering: the saved hex never changes; ring and check are derived when drawn (ring darkened in lightness until 3:1, check white or ink). Very light colours also get the derived ring as the edge of the done dot so it does not vanish on cream.
  • Dark mode (G4-6): the same derivation runs against dark surfaces; no dark colours chosen here.
  • Tablets (Round 2): iPad uses the Mac-style popover at regular width; Android tablets the M3 sheet as a side sheet or dialog.
  • App colour (Settings) also takes any colour via Edit palette / Custom…: needs a saved accent hex in settings (same must-ask); buttons and links use a derived shade that keeps 4.5:1, the saved colour never changes.
