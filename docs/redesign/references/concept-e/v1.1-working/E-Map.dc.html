B. Responsive behaviour map

Proposed breakpoints PROPOSED content-driven, not 600/840

Minimum content widths, measured from E's 1280 frames and today's code:

  • Thread column: 320 minimum (time label + dot lane + one readable title line); drawn at 388–408 (v1.0), 290 in E-Minimal's Mac right column, 510 on its web.
  • Now card: 320 minimum (big dot + title + Done / Focus / Need more time? wrapping to two rows); drawn at 356–372 (v1.0); E-Minimal Now pane 790 Mac, 560 web.
  • Inspector: 300 (drawn at 300; today's editor panel is 420).
  • Sidebar: 216 (drawn; E-Minimal 200); rail 80.
  • Inbox column: 240.
  • Week grid: 136 per day + 56 gutter (drawn) → 7 days need 1008.

Extra rules PROPOSED

  • Week day count = floor((grid width − 56) / 136), between 3 and 7. All 7 days fit beside the sidebar from ~1224; beside sidebar + Inbox + inspector only from ~1764, so at 1280 Week scrolls (Mon–Thu, as drawn).
  • Short height (< 480, phone landscape): keep the compact shell whatever the width.
  • Large text (≥ 150 %): drop one class, because every minimum above grows with text.
  • Hinge: never place a pane across a fold; panes snap to each side.
  • Mac minimum window (960 × 640 today) lands in medium; either design medium for Mac or raise the minimum to 1160 — owner choice.
  • Today's 600 / 840 split gives a 339 px Today at 840 with the editor open and an "expanded" that is really rail + phone pager (PLATFORM_BASELINE.md §3); these numbers avoid that.

E design rules

  • One day, one thread. Every task is a dot on the thread: done solid, now a ring that fills with time, ahead outlined; the icon stays in the dot; overlaps meet at a knot.
  • Today first, Now when asked. Full phones open on Today's thread; Now (one big dot, the horizon, next) leads in minimal on phones and on Mac/web (E-Minimal), with the Day beside it on wide windows.
  • One Day menu instead of ⋯. Replan · Plan · Reflect · View · Share, shown in each platform's own form: iOS pull-down, M3 menu, Mac menu bar, web popover.
  • Add in two taps, nothing written before Accept. Task, Brain dump and Routine are modes of Add; pasted lists and generated plans always go through the proposal sheet.
  • One task surface. A sheet with detents on phones, an inspector on wide windows (in minimal, the task screen takes the Day column and closes back to the Day); Done, Move, Shift the rest and Focus come first; Move always works.
  • Native chrome, one identity. Liquid Glass on iPhone, translucent tonal M3 on Android, vibrancy sidebar + menu bar on Mac, solid surfaces with path URLs and single-key shortcuts on web; sheets stay solid.
  • Settings sits where each platform keeps it. Avatar on phones, ⌘, window on Mac, sidebar footer on web and tablets.
  • Minimal hides, never removes; no shame. Every hidden feature has a named way back; no streaks, no red for unfinished; colour is never the only signal.
