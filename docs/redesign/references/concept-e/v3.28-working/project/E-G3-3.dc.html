Why A

  • It is what you approved: you asked for C's typography in E (ED-012, “in Place”), and every approved board, G3-1 and G3-2 included, is drawn and measured in Manrope.
  • One identity: a bundled content face looks the same on iPhone, Android, Mac and web; chrome stays native (K6), so each platform still feels native.
  • Against B: Inter is neutral and already built, but it would make E look like today's app and every board would need re-checking for line breaks.
  • Against C: content would look different on every platform and lose the brand voice; the orb's 800 numeral would vary by OS.
  • Cost of A: one font file and its licence change in the app (no new package), plus golden updates. Not done now; it is a Step 9 / implementation item and needs an ADR because it changes the brand face.

Accessibility

  • Larger text: all three scale with Dynamic Type and Android font scale; Flutter applies the user's text scale to bundled fonts too.
  • Legibility: the specimen row “Il1 0O rn m” shows the confusable shapes; check them at 13–14 px, the smallest content size.
  • Bold text setting: the app's bold-text handling works the same with any face (A and B are variable fonts with every weight).
  • Contrast: unchanged; colour is not part of this decision.

Platforms

  • iPhone, iPad, Mac: chrome SF in every option (K6); content as chosen.
  • Android: chrome Roboto (system) in every option; content as chosen.
  • Web: chrome a system stack; content as chosen, served with the app (no Google Fonts call at runtime).
  • Minimal: the same face as Full; the orb numeral follows it (G3-2).

Tablet implications (recorded, not drawn)

  • iPad and Android tablets: the same content face and type roles; sizes follow the width class, not the device.
  • Round 2: part of the tablet checklist.
