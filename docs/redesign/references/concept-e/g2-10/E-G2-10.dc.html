G2-10 · One keyboard scheme

Decision board · no E board changed · keys shown on E-FullA-v2, E-Minimal, E-G2-8 and E-G2-9 are proposals until this is decided

The built app, E-FullA-v2 and E-Minimal use different keys, and several clash with macOS or the browser. The proposal is one scheme for both modes: built keys kept where they are safe, E-FullA-v2's fixes for the clashes, E-Minimal's keys where they do not clash. The one real choice is what ⌘1–4 mean in Full: views (A) or places, as built (B, recommended).

Rules for the proposal

  • Never bind a reserved key: macOS standard menu keys, iPadOS and Android system keys, and keys browsers keep for themselves.
  • Same key, same meaning in both modes. Only ⌘1–4 follow what each mode shows (the sidebar or tabs you see).
  • Text fields win: ⌘← ⌘→, ⇧⌘→, ⌘⌫ and ⌘Z edit text while you type; single web keys are off in fields.
  • Every command stays in a menu (menu bar, Day menu, context menu) and in ⌘K, so a key is never the only way.
  • Keep what is built unless it clashes or breaks the rules above.

Why B

  • Nothing built moves: ⌘1 Today and ⌘2 Inbox keep working for current users.

  • Cost: Day and 3 Days have no number key on Mac (web keeps d and 3). E-FullA-v2's View menu labels change.
  • Changed from the register: the register recommended A before G2-9. Your G2-9 answer asked to preserve built behaviour, which favours B.

If you approve (A or B)

  • E-FullA-v2: G2-8 and G2-9 keys become approved; under B the View menu shows Today · Inbox · Week · Month on ⌘1–4; the web Day menu's b becomes ⇧N; the web hint bar adds k.

  • Phones: no change (no keyboard by default).
  • Built app (later, not now): ⌘D Done → ⌘↩ (⌘D becomes Duplicate); web ⌘/Ctrl 1–4 → single keys; web ⇧P → p; the single-key setting. Under A also ⌘1 and ⌘2.
  • Not in this decision: web routes (G2-11), custom remapping (only on/off), a key for Need More Time.

Accessibility

  • Never the only way: every command is in a menu and in ⌘K, and VoiceOver reads the key with each menu item.
  • Discoverable: ⌘/ (built) on Mac, iPad and Android; ? on the web; keys shown in menus and web tooltips.
  • Text first: no single key fires while a text field has focus; editing keys always edit text.
  • Off switch: single-key web shortcuts can be turned off (WCAG 2.1.4).

Tablet implications (recorded, not drawn)

  • iPad with a keyboard: the same ⌘ scheme (built already uses ⌘ on iOS). Holding ⌘ shows iPadOS's shortcut overlay only for commands registered natively; Flutter needs a native path. Unverified.
  • Android tablets, foldables, Chromebooks: the Ctrl column. Meta+/ opens Android's keyboard shortcuts helper only for shortcuts the app publishes. Unverified in Flutter.
  • Which ⌘1–4 a tablet gets follows the mode and layout it shows (Full or minimal), decided in the Round 2 tablet checklist.
  • Round 2: check system-reserved keys per OS version on real devices.
